# Panneau « Outils » — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un bouton « Outils » à droite de Files et Changes ouvre un panneau avec sa barre (Git, Terminal) : une interface git façon lazygit (changements, branches, graphe) et un terminal par space.

**Architecture:** Tout vit dans le mod `antoine` (`~/.config/herdr-app/mods/antoine/`) et la disposition `layouts/antoine.json`. Le nœud « outils » du panneau de droite est une colonne : la barre (mod `antoine`, `view: "outils-bar"`), la partie Git (`view: "git"`), puis un bloc `{ "terminal": "<adresse>" }` dont la barre change l'adresse selon le space avec `layout.set`. Règles pures dans `outils.js`, `gitpanel.js`, `gitlog.js`, `lanes.js`, testées avec Node depuis `tests/`.

**Tech Stack:** JavaScript des mods Herdr (`herdr`, `gpui-kit`, `gpui-base`), `exec("git", …)`, `hc run`, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-09-outils-design.md`

## Review Focus

- Une frappe dans le terminal Outils ou dans Claude Code ne déclenche jamais une action git ; la partie Git ne réagit qu'après un clic sur l'un de ses cadres → test `keyAction` ignore tout sans cadre actif (tâche 3) et essai manuel (tâche 5).
- Dépôt sans commit (HEAD absent), dépôt en plein rebase/fusion, ou dossier hors dépôt : pas de plantage, message clair → tests `parseBranches`/`parseLog` sur sortie vide (tâches 2, 3) et message « Pas de dépôt git ici » (tâche 5).
- Fichier dont le nom contient des espaces, des accents ou commence par `-` : indexation correcte → test `stageArgs` avec `--` (tâche 3).
- Nom de branche invalide ou déjà pris dans la fenêtre `n` : refusé avec un message, la fenêtre reste ouverte → test `branchError` (tâche 3).
- Changer de space vite, plusieurs fois : jamais deux terminaux pour un même space → test `terminalNameFor` stable + `termFor` (tâche 1) et lancement gardé par un drapeau « en cours » (tâche 6).

### Task 3: Règles pures de la partie Git (`gitpanel.js`)

**Files:**
- Create: `~/.config/herdr-app/mods/antoine/gitpanel.js`
- Test: `tests/gitpanel.test.mjs`

**Interfaces:**
- Consumes: rien (pur).
- Produces:
  - `STATUS_ARGS`, `parseChanges(porcelainZ) → {path, kind: "M"|"A"|"D"|"U"|"R", staged: boolean}[]` (`git status --porcelain=v1 -z --untracked-files=all`).
  - `BRANCH_ARGS` (`for-each-ref --format=%(refname:short)%00%(HEAD) refs/heads`), `WORKTREE_ARGS` (`worktree list --porcelain`), `parseBranches(refsOut, worktreesOut, root) → {name, current: boolean, worktree: string|null}[]` (`worktree` : chemin du worktree qui l'a sortie, autre que `root`).
  - `stageArgs(change) → string[]` : `["add", "--", path]` si non indexé, `["restore", "--staged", "--", path]` sinon (`["rm", "--cached", "--", path]` pour un fichier supprimé déjà indexé si `restore` ne convient pas — vérifier sur un dépôt jetable).
  - `commitArgs(message) → string[]` = `["commit", "-m", message]`.
  - `checkoutArgs(name)`, `createArgs(name)` = `["switch", "-c", name]`, `deleteArgs(name)` = `["branch", "-d", name]`.
  - `branchError(name, branches) → string|null` : « Nom vide », « Cette branche existe déjà », « Nom de branche invalide » (règles de `git check-ref-format --branch` : pas d'espace, pas de `..`, pas de `~^:?*[\`, pas de `-` au début, pas de `/` à la fin, pas de `.lock`).
  - `refusal(action: "checkout"|"delete", branch) → string|null` : pour une branche de worktree, « Cette branche est ouverte dans un worktree (<chemin>) » ; `delete` sur la branche actuelle : « Impossible de supprimer la branche actuelle ».
  - `keyAction(frame: "changes"|"branches"|"graph"|null, key: string) → "stage"|"commit"|"checkout"|"new"|"delete"|"up"|"down"|null` : `changes` : `space`→stage, `c`→commit ; `branches` : `space`→checkout, `n`→new, `d`→delete ; tous : `up`/`down` ; `null` → toujours `null`.
  - `gitMessage(result: {code, stderr}) → string` : la première ligne utile de stderr (sans le préfixe `error: `/`fatal: `), sinon « La commande git a échoué ».

- [ ] **Step 1: Tests** — un par fonction, valeurs ci-dessus, dont :

```js
assert.deepEqual(P.stageArgs({path:"-a b é.txt", kind:"M", staged:false}), ["add", "--", "-a b é.txt"]);
assert.equal(P.keyAction(null, "space"), null);
assert.equal(P.keyAction("graph", "c"), null);
assert.equal(P.branchError("feat x", []), "Nom de branche invalide");
assert.equal(P.branchError("main", [{name:"main"}]), "Cette branche existe déjà");
assert.match(P.refusal("checkout", {name:"wt", worktree:"/tmp/wt"}), /worktree/);
```
  plus un test sur dépôt jetable : `parseBranches` avec un `git worktree add` marque la branche du worktree ; un dépôt sans commit rend `[]` sans erreur.
